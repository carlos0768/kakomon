# 問題出題の要件定義 (出題要件定義書の仕様)

この文書は 2 層に分かれる。

- **A. システム要件**: 過去問分析 → 予想問題生成 → 添削 → 弱点分析 のシステムが満たすべきこと。
- **B. 出題要件定義 (ExamSpec)**: 過去問を分析して得られる「この試験はこう作られている」という仕様書。作問 LLM への入力そのもの。B は試験ごとに `analyze` ワークフローが自動生成し、管理者が確認・修正して確定する。

> 現時点でリポジトリに過去問 PDF は無いため、B の具体的な数値 (分野比率など) は空欄である。管理者が `data/past-exams/` に PDF を置いて `npm run admin -- ingest` → `analyze` を実行すると、`docs/specs/<specId>.md` にこの様式で書き出される。

---

## A. システム要件

### A-1. 役割

| 役割 | できること | できないこと |
|---|---|---|
| 管理者 (サイト運営者) | 過去問 PDF の登録、傾向分析の実行、要件定義の確認・修正、予想問題の生成・校閲結果の確認・承認・公開、出力 (HTML/PDF) の取得 | — |
| 受験者 (ユーザ) | 公開済み予想問題の閲覧と解答、添削結果の閲覧、受験履歴の閲覧、2 回以上受験後の弱点分析 | 問題の生成・編集、正解データへのアクセス |

### A-2. 機能要件

| ID | 要件 | 実装 |
|---|---|---|
| F-1 | 写真を束ねた PDF を含む過去問 PDF から、全設問 (問題文・選択肢・正解 (あれば)・分野・設問型・難易度) を構造化して保存する | `ingest-exam` ワークフロー / `exam-extractor` エージェント |
| F-2 | 原本の見た目 (用紙・段組み・番号書式・選択肢ラベル様式・フォント系統) をレイアウトプロファイルとして記録する | `layoutProfileSchema` |
| F-3 | 複数年度の過去問を横断して、分野傾向・作問方法・難易度分布・作問ルール・次回予想を分析し、出題要件定義 (B) を生成する | `analyze-exam` ワークフロー / `exam-analyst` エージェント (過去問ツール付き) |
| F-4 | 要件定義に基づき、別の LLM (作問エージェント) が予想問題 1 回分を生成する。作問 LLM は過去問をツールで参照できる | `generate-exam` ワークフロー / `exam-generator` エージェント |
| F-5 | 生成物を校閲 LLM が要件定義・過去問と照合し、blocker があれば自動で 1 回改訂する | `exam-reviewer` エージェント |
| F-6 | 管理者が承認するまで公開しない (承認待ちで停止し、後から再開できる) | `admin-approval` ステップ (suspend/resume) |
| F-7 | 承認後、原本の見た目を再現した HTML と PDF を出力し、受験者に公開する | `render-and-publish` ステップ |
| F-8 | 受験者は選択肢を選ぶだけで解答でき、提出すると LLM が添削する。誤答については「選んだ選択肢がなぜ誤りか」と「正解の根拠」を解説する | `grade-attempt` ワークフロー / `exam-grader` エージェント |
| F-9 | 2 回以上受験した受験者について、分野・トピック・設問型ごとの正答率と、出題比率を加味した弱点の優先度、原因と学習計画を提示する | `weakness-analysis` ワークフロー / `exam-coach` エージェント |
| F-10 | 受験者向け API は正解・解説・根拠を一切返さない | `toPublicQuestion()` |

### A-3. 非機能要件

- **正誤判定は決定的に行う**: LLM に採点させず、保存された正解ラベルと照合する。LLM は解説文の生成のみ担当し、失敗しても選択肢の根拠 (rationale) から組み立てた解説を返す。
- **再現性**: 要件定義・生成物・校閲結果・承認は DB に残し、どの要件定義からどの予想問題が作られたか追跡できる (`exams.spec_id`)。
- **置換可能性**: モデル名・DB・埋め込みモデルは環境変数で差し替えられる。
- **安全性**: Claude の安全分類器が拒否した場合はサーバ側フォールバックで別モデルに切り替える。管理者 API はトークンで保護できる。

### A-4. 受け入れ基準

1. 過去問 PDF を 1 つ取り込むと、設問数が原本と一致し、判読不能箇所が `extractionNotes` に列挙される。
2. 2 年度以上取り込んだ状態で `analyze` を実行すると、B の全項目が埋まった要件定義が生成され、分野比率の合計が 1 になる。
3. `generate` を実行すると、校閲スコアと指摘一覧つきの下書きが `review` 状態で保存され、承認するまで受験者 API に出ない。
4. 承認すると `data/out/<examId>.html` と `.pdf` (Chromium がある環境) が生成され、受験者 API に出る。
5. 受験者が提出すると、各設問に正誤・選んだ選択肢が誤りである理由・正解の根拠・ひと言が付いて返る。
6. 同一受験者が 2 回提出すると弱点分析が実行でき、1 回では 400 で拒否される。

## B. 出題要件定義 (ExamSpec) の仕様

`analyze` が生成し、管理者が確定する仕様書。スキーマは `src/mastra/schemas/spec.ts`、Markdown 出力は `npm run admin -- export-spec <specId>`。

### B-1. 構成

| 節 | 内容 | 根拠の取り方 |
|---|---|---|
| **総括 (summary)** | 試験の性格 (暗記型か応用型か、法令改正への追随度、年度間の安定性) を管理者が 1 分で読める分量で | 全回を通読した所見 |
| **形式要件 (format)** | 設問数、選択肢数、単一/複数正解、制限時間、問題文の文体 (常体/敬体、「最も適切なもの」「誤っているもの」の使い分け)、選択肢の文体・長さ・並び順の規則、番号付け | 原本の指示文と実設問 |
| **分野構成 (domains)** | 大分類ごとの出題比率 (合計 1) と想定出題数。各大分類の中にトピック (小分類) と分野内比率、頻出キーワード、過去の出題例 (`examId:設問番号`)、傾向 (増加/横ばい/減少/新規) | `get-question-stats` の集計 + 実設問の参照 |
| **作問方法 (patterns)** | 設問型 (定義・用語 / 正誤判定 / 計算 / 事例適用 / 手順・順序 / 比較・分類) ごとの比率、典型的な問い方のテンプレ、誤答選択肢の作り方 (用語入替、数値改変、部分的真、否定語、時系列入替 など)、例 | 設問型の集計 + 選択肢の観察 |
| **難易度分布 / 認知レベル分布** | 難易度 1〜5 と 知識/理解/応用/分析 の比率 | 抽出時に付与した値の集計 |
| **作問ルール (rules)** | must (必ず守る)、mustNot (禁止)、styleGuide (表記) | 原本から読み取れる暗黙の規則の言語化 |
| **次回予想 (forecast)** | 重点トピックと理由、優先度 | 出題周期・増減・未出題の重要項目 |
| **出典 (sourceExamIds)** | 分析に使った過去問 ID | — |

### B-2. 作問 LLM に対する拘束力

作問エージェントは生成前に `get-exam-spec` で B を読み、次を満たす設計表を作ってから書く。

- 分野比率・設問型比率・難易度分布を ±1 問の範囲で守る。
- forecast の `high` トピックは必ず含める。
- rules.mustNot (過去問の丸写し、曖昧な正解、根拠のない事実) に違反しない。設問ごとに `search-past-questions` で類題を確認する。
- 全選択肢に rationale を付ける (添削の根拠になる)。

校閲エージェントは同じ B を読み、逸脱を `要件逸脱 / 正解の曖昧さ / 過去問との重複 / 誤答選択肢の弱さ / 表記 / 事実誤認` に分類して指摘する。blocker が 0 件かつスコア 70 以上で管理者レビューに回る。

### B-3. 管理者の確認ポイント

生成された B を確定する前に、管理者は次を確認する。

1. 分野名の粒度が揃っているか (同じ内容が別名で分かれていないか)。
2. 比率が直近年度の実感と合うか。古い年度に引きずられていれば `--focus "直近3年を重視"` を付けて再分析する。
3. mustNot に、法改正などで出題されなくなった論点が入っているか。
4. forecast の理由に納得できるか。

## C. 見た目の再現に関する要件

- 管理者が事前に送る「写真を束ねた PDF」から、抽出時にレイアウトプロファイル (用紙サイズ、縦横、段組み、ヘッダ/フッタ文言、冒頭注意事項、設問番号書式 `問{n}`、選択肢ラベル様式 (数字/丸数字/カタカナ/英字/括弧数字)、縦組み/横組み、フォント系統、本文サイズ、解答用紙の有無、その他の特徴) を記録する。
- 予想問題は参照する過去問 (`--ref`、省略時は最新年度) のレイアウトプロファイルをそのまま引き継ぎ、HTML/CSS で組版する。選択肢ラベルは原本と同じ表記に変換する。
- PDF 化は Chromium (playwright-core) で行い、`@page` の用紙サイズを尊重する。Chromium が無い環境では HTML のみ出力し、理由を返す。
- 画像・図表を含む設問は現状テキストのみ再現する (図版は今後の拡張: 抽出時に図の説明を `passage` に残し、作問時に図無しで成立する設問に限定する運用)。
